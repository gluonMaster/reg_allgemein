# Автоматическая цена занятия и демонстрационный прайс в preview

Дата: 2026-09-15. Статус: **ТЗ подготовлено; реализация и публикация не выполнены**.

## 1. Результат и границы

Родитель выбирает занятие и видит корректную цену в каталоге/заявке.
Администратор выбирает то же занятие при подготовке договора; цена и её источник
подставляются автоматически. Опубликованный preview содержит небольшой,
согласованный набор привлекательных синтетических занятий и работающий прайс.
Владелец явно включил в scope **каталог, заявки и подготовку договора** и требует
максимально быстрого и простого исполнения.

Это отдельный пакет после UI-работ: он включает данные и ценовую интеграцию,
которые не входили в прежний UI-пакет. Подготовка этого ТЗ не является запуском
реализации или разрешением выполнять сейчас remote mutations.

Источники правил: [PRICE-01–05, CAT-03, REQ-03](../spec/MVP_SPEC.md),
[PRICING](../domain/PRICING.md), [CONTRACTS](../domain/CONTRACTS.md),
[COURSES](../domain/COURSES.md), [импорт](../operations/IMPORT_PIPELINE.md).
Новые UI-критерии: [приёмка цены](../spec/ACCEPTANCE_CRITERIA.md#6-цена).
На дату подготовки в [OPEN_QUESTIONS](../spec/OPEN_QUESTIONS.md) открытых вопросов нет.

## 2. Что уже есть и чего не хватает

Read-only проверка опубликованного preview 2026-09-15 обнаружила:
`price_versions = 0`, `price_rules = 0`, `course_pricing_profiles = 0`.
Две опубликованные синтетические группы имеют занятия по 90 минут;
их расчёты возвращают `needs_admin_review / UNKNOWN_OR_AMBIGUOUS_MAPPING`.
Прежние тестовые договоры содержат суммы без привязки к прайсу.

Переиспользовать существующие механизмы:

| Механизм | Реализация |
| --- | --- |
| Импорт, валидация, активация версии | `ImportRepository`, `parsePriceWorkbook` |
| Ценовой профиль группы | `CoursePricingAdminRepository.configureCoursePricing` |
| Расчёт и проверка актуальности | `PricingService`, `PricingRepository`, `decisions.ts` |
| Тариф заявки | `IndividualRequestService` |
| Создание, отправка и принятие договора | `ContractService`, существующие routes |

Вывод цены в `catalog/+page.svelte` и обоих тарифов в
`requests/new/+page.svelte` уже реализован; `IndividualRequestService` уже
назначает тариф при создании заявки. Эти части не реализовывать заново:
подключить данные и менять только недостающие подписи/переходы или подтверждённые
несоответствия. Основная новая функциональность — ценовой блок договора.

Есть два конкретных стыка для доработки: локальная команда импорта прайса
не обслуживает remote preview; public quote создаётся без owner/child,
тогда как договор проверяет quote конкретного родителя и ребёнка.
Нельзя просто передать ID публичного расчёта в договор или ослабить эту проверку.

## 3. Минимальная доработка интерфейса и сервера

### Родитель

- Подключить прайс к существующему выводу базовой цены в карточках групп;
  дополнить подпись видом договора. На странице пробного обозначать её как цену последующих
  регулярных занятий; не выдавать месячный тариф за стоимость пробного урока.
- Добавить в каталог два компактных входа в существующие заявки:
  «Nachhilfe — Lernförderung» и «Индивидуальные занятия». Это карточки услуг
  со ссылками на `/requests/new?kind=nachhilfe|individual`, без выдуманного
  расписания индивидуальных занятий и без новых видов заявок.
- Сохранить существующий вывод тарифа на форме и странице заявки, проверить
  правильные единицу и плательщика.
  Для индивидуального занятия использовать server config, для Nachhilfe —
  существующую фиксированную ставку финансирования. Эти ставки не переносить
  в групповой прайс; правила `PRICE-02` сохраняются.
- Смена выбранного занятия/типа обновляет цену; прежняя сумма не остаётся
  на экране при загрузке, ошибке или переключении. Сумму пользователь не вводит.

### Администратор: один блок в существующей форме договора

- Добавить выбор типа услуги и конкретного источника: опубликованная группа
  либо одобренная individual/Nachhilfe-заявка выбранного родителя и ребёнка.
  Использовать понятные названия; IDs остаются внутренними значениями options.
  Существующие выбор/поля родителя, ребёнка, даты начала и срока предложения
  сохраняются; большой пошаговый мастер в scope не входит.
- После выбора сервер возвращает цену, единицу, плательщика, вид договора
  и допустимый источник. Цена видна отдельно от технических полей, read-only.
  Для Nachhilfe выбор заявки не заменяет approved funding и проверку его дат.
  Использовать существующие page loads/actions и локальное состояние формы;
  отдельная подсистема синхронизации, polling и универсальный quote API не нужны.
- При создании draft сервер сам формирует ценовую часть render input:
  суммы, `lineItems`, source/mode, единицу, плательщика и ссылки на расчёт/прайс.
  Связь услуги берётся из выбранной группы/заявки. Не требовать ручного ввода
  price IDs или редактирования ценовых фрагментов JSON.
  Остальная часть существующего JSON-редактора может остаться для скорости
  реализации; новую генерацию всех юридических/персональных полей не строить.
- Для группы создать новый owner/child-bound quote штатным расчётом;
  публичный quote не перепривязывать. Клиентские суммы и ссылки не являются
  источником истины. Перед сохранением и отправкой проверить актуальность
  условий. При изменении показать новую цену и потребовать явного повторного
  подтверждения; не отправлять договор с незаметно изменившейся суммой.
  Достаточно обновлённой суммы, пояснения и повторного обычного действия в этой
  форме; новый approval workflow, роли и таблицы согласований не вводить.
- Для individual взять сохранённый тариф выбранной заявки, проверяемый
  существующим contract flow; не переписывать старую заявку новым config.
  Для Nachhilfe сохранить фиксированную funded-ставку и ограничения периода.
- Обычный новый путь автоматической цены не допускает обход через свободный
  JSON/отсутствующий quote. Отдельный существующий manual override сохраняет
  свои reason/confirmation/audit правила. Старые immutable предложения и PDF
  не переписывать, исторический preview lifecycle не ломать задним числом.
- Ошибки выбора, отсутствующего прайса, funding и устаревшей цены объяснять на
  DE/RU; сохранять остальные введённые данные. Использовать существующие
  компоненты и оформление, проверить 390 px и обычный desktop.

## 4. Небольшой синтетический набор

Переиспользовать две существующие **подтверждённо синтетические** группы,
сохранив их ID, связи и расписание. Изменить только их публичные названия и
предметы, необходимые для понятного показа; исторические snapshots сохраняются.

| Текущая группа | Новое название | Вид договора | Явный price key / предмет |
| --- | --- | --- | --- |
| TEST/ENTWURF Jahresgruppe | Mathe-Werkstatt · Entdecken & Knobeln | group_yearly | Mathe / Mathe |
| TEST/ENTWURF Monatsgruppe | Kunstatelier · Farben & Fantasie | group_monthly | Kunst / Kunst |

На preview показать ненавязчивую общую отметку «Демонстрационные данные».
Маркировку `TEST/ENTWURF` в договорных документах сохранить. Для карточек услуг
использовать короткие DE/RU пояснения: помощь с учебными предметами по направлению
Jobcenter/Sozialamt; индивидуальное занятие по согласованию с бюро.
Иллюстрации, генерация изображений, новый дизайн и новые персональные данные
для этого не нужны.

Один синтетический прайс текущего периода, два ключа, по шесть exact-строк
на ключ. Для обоих ключей использовать эту **демонстрационную**, не production,
сетку; `Dauer = 90`, один соответствующий предмет в vector:

| Kinder | Preis: €/месяц, годовой договор | Sonderpreis: €/месяц, месячный договор |
| --- | --- | --- |
| 1 | 92 | 120 |
| 2 | 76 | 100 |
| 3 | 64 | 84 |
| 4 | 56 | 72 |
| 5 | 50 | 66 |
| 6 | 46 | 60 |

Итого 12 правил; суммы в БД — integer cents. Профили обеих групп confirmed,
длительность берётся из существующего расписания, не из fallback. В каталоге
ожидается строка по фактической occupancy на дату расчёта, а не всегда 46/60 €.
Исходные synthetic fixtures компактны, детерминированы, имеют стабильные ключи.
Новый запуск с тем же набором не создаёт дубли; drift не затирается молча.

Новые аккаунты, дети, фиктивные записи для наращивания occupancy и заранее
«одобренные» документы не входят в seed. Для проверки договоров использовать
доступные синтетические учётные записи/заявки и реальные обязательные prerequisites;
истекшее направление или отсутствие ребёнка не обходить вставкой fake approval.

## 5. Реализация и публикация коротким пакетом

1. **Локально:** данные, компактный блок выбора/цены, server binding и проверки.
   При необходимости добавить один узкий preview-only операторский скрипт,
   вызывающий существующие import/profile методы через remote D1 transport.
   Не строить универсальный remote-import framework или редактор прайсов.
   Формат synthetic fixture выбрать по существующим helpers: отдельный Excel-
   файл и новый parser не являются требованиями. Штатная валидация и audit
   импорта/профилей обязательны независимо от формата.
   Предпочтительно обойтись существующей схемой; новую миграцию добавлять только
   при доказанной необходимости, не переписывать применённые миграции.
2. **Подготовка публикации:** exact target из
   [active state](STAGE_13_ACTIVE_STATE.md), fingerprint существующего набора,
   ожидаемые изменения и rollback/containment. Нельзя включать в demo-seed
   production, реальные Office-источники, legacy reimport или замену всей БД.
3. **Опубликованный preview:** code deploy, если код изменён; staging/validation
   и activation синтетического прайса; настройка двух профилей и подписей.
   Разделить фактические writes на штатные атомарные операции. После каждой
   попытки выполнить read-only postcondition и отдельный docs-only checkpoint
   commit по `AGENTS.md`. Не повторять failed/ambiguous write вслепую.
4. **Завершение:** проверка ниже на реально опубликованном портале и короткий
   handoff с адресом preview, подтверждёнными результатами и оставшимися ограничениями.

У первой price version нет предыдущей: заранее проверить её штатный rollback.
Если он неприменим, подготовить containment — временно снять с публикации только
затронутые demo-группы с сохранением истории; не восстанавливать всю живую D1
поверх появившихся пользовательских данных. Deploy откатывается на сохранённую
совместимую Worker version. Access и работающие provider-настройки сохраняются.

Учесть фактический код: GET каталога вызывает `createPublicQuote` и пишет
`price_quotes`. Такой remote smoke является mutation, а не read-only проверкой.
Для postcondition использовать bounded SELECT; при браузерной приёмке учитывать
созданные quotes и обычные audit/session effects в checkpoint.

## 6. Проверки и критерий завершения

Во время разработки — один focused run изменённых import/pricing/contracts/
requests suites и affected browser scenarios. Добавлять проверки новых стыков,
переиспользовать существующие tests формул/импорта/ownership. Перед deploy
материального runtime diff — один полный gate по `AGENTS.md`:
check, Vitest, Chromium, build, docs/release checks. После docs-only checkpoint
полный suite не повторять. Новые P2/P3 не открывают дополнительный review-loop.

| Приёмка | Минимальное доказательство |
| --- | --- |
| Две группы получают exact-цену | В local и remote: активная версия, 12 valid rules, два confirmed profiles; сохранённые quotes имеют rule/version, `EXACT_RULE`, сумму по count/date |
| Правильная семантика всех трёх услуг | DE/RU UI: группа — базовая месячная цена; individual — €/45 мин за счёт родителя; Nachhilfe — funded €/45 мин, без суммы к оплате parent |
| Цена автоматически попадает в договор | Local: два групповых вида + individual + Nachhilfe, без ручного ввода сумм/price IDs; draft, render input и сформированный источник договора содержат согласованные сумму/единицу/плательщика; group quote связан с нужными owner/child |
| Подмена или устаревшие данные не проходят | Один focused набор: foreign child/request/quote, подменённая сумма/source, changed price/occupancy/start date, неподходящий funding; ошибка сохраняет форму |
| Переключение формы корректно | Browser: быстрое переключение услуги не возвращает старую цену; выбранные service/template/billing согласованы; нет overflow на 390 px |
| Seed безопасен и повторяем | Local: повтор — no-op, mismatch — остановка; проверен rollback/containment первой версии; remote — bounded read-back каждой операции |
| Функция доступна в опубликованном preview | Открыть новые карточки/формы; штатно сохранить свежие тестовые drafts для двух групповых видов и двух типов заявок и сверить цену/связи в D1; prerequisite failures фиксируются, а не выдаются за успех |

Изменённый ценовой payload проверяется вместе с формированием источника договора
в существующих local contract tests. Полный внешний AV/PDF/email/Telegram
lifecycle не повторяется, если renderer/templates/provider adapters не изменены
и нет конкретного нового риска, требующего remote проверки. Отправка, принятие
и активация договора остаются отдельными действиями; создание draft их не выполняет.
Этот пакет не объявляет весь `full-manual-preview` или production gate пройденным.

## 7. Результат проверки `spec-rightsize`

Структурного разрастания нет. Уточнено переиспользование уже работающих тарифных
блоков, существующей формы подтверждения и import helpers. Исключены повторная
реализация родительских тарифов, новый approval workflow, обязательный Excel-
артефакт и универсальные quote/import API.

12 строк нужны для двух ключей и всех поддерживаемых lookup counts, а четыре
варианта draft — для двух групповых видов договора и разных hourly-веток.
Это небольшой объём данных; сокращение этих проверок не заменено предположением
об одинаковом поведении. Сохранены ownership, идемпотентность, rollback/containment
и обязательный release gate репозитория.

Вне пакета: новый pricing engine, перенос hourly-тарифов в Excel, редактор прайса,
полный мастер договора, платежи, пересмотр старых договоров и массовый seed семей.
Ограничение предлагаемого быстрого решения: JSON вне ценового блока остаётся.
Существенное расширение до этих функций требует отдельной оценки scope.
Ожидающих решения вопросов нет. Проверка проведена по коду и документам;
runtime, remote-интеграция и сроки исполнения этим проходом не подтверждены.
